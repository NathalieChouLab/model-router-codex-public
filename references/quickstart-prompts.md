# Try Model Router

These prompts are examples, not recorded benchmark results. Run against a test project first.

## Explore a repository

> Use mr_scout to identify the application entry point, test commands and configuration files. Return exact paths and short evidence. Do not edit.

## Fix a failing test

> Apply Model Router. Ask mr_debugger to reproduce the failure and identify the cause. Once the cause is established, have mr_builder apply a bounded fix, mr_tester write an independent regression test, and mr_reviewer review the actual diff and results. Stop if scope or risk increases.

## Build against a changing API

> Have mr_researcher verify the current official API documentation. Cite versions, relevant sources and uncertainty. Then delegate the approved implementation and independent checks. No deployment.

## Plan a migration

> Ask mr_architect to compare two migration strategies, define acceptance criteria, risks and rollback. Stop before edits until I approve a plan.

## Improve a UI

> Ask mr_designer to review the current screenshots or rendered page against the design brief, accessibility and responsive behavior. Return a prioritized list with evidence. Implement only the agreed changes.

## Write documentation

> Have mr_writer draft documentation from the existing code and verified facts, then mr_reviewer check commands and unsupported claims.
